The first stable release, and what a reader can now rely on. The core promise is unchanged: a
submit is acknowledged only after a durable commit, acknowledged runs survive `kill -9` and
reboots, and the framed append-only journal — one writer, exclusive lock — is the only authority.
Journal records are now versioned: new records carry `v: 2`, readers accept v1 forever and refuse
unknown future versions rather than guess, and `--journal-format` plus `deploy/format-guard.sh`
refuse an upgrade or rollback to a binary that can't read the journal — failing closed, not eating
state.

**Per-client limits ship.** One address gets 100 requests/s by default (`429 rate_limited` with
`Retry-After`), connection caps for untrusted peers and separately for trusted proxies, and
`--trusted-proxy` CIDRs that decide whose `CF-Connecting-IP` is believed — anyone can set that
header, so it's believed from no one else. IPv6 keys at /64 with a /48 aggregate.

**Capacity is measured, not assumed.** Two honest numbers: a 12-core laptop sustained 100
submits/s — 1,000,000/1,000,000 done, p99 41 ms — and a 4-core CI runner topped out near ~85
completions/s, so a 100/s offer had 835,397 accepted then refused the rest `503 at_capacity` at
the 100,000-live-run bound. The CI miss is kept as evidence, not rerun until green: over-offered,
the server keeps completing at its own rate and refuses the overflow by name. Your own host gets
the same probe before traffic — see [Capacity](/self-hosting/capacity/).

**The Inspector covers everything now** — submit, list, detail, spec read-back, cancel,
diagnostics, compact, backup — with two-step confirms on mutations, keys in `sessionStorage` only,
light/dark tokens and a phone layout that stays unclipped at 390 px. And a deploy kit ships with
the repo: hardened systemd unit, Caddyfile with `lb_try_duration 15s`, Cloudflare ranges feeding
both trust boundaries, daily encrypted backups under a 7-day lock, and upgrade/rollback scripts
behind the format guard.
