A rollback-safety release. The review of the in-progress workspace work found two ways v1.0.1 was
an unsafe floor to roll back to, and both are fixed here.

**Tenant runs are parked, never executed.** v1.0.2 replays the newer v3 record format faithfully,
but its handler registry is workspace-blind — running a workspace ≠ 0 job would POST that tenant's
input and idempotency key to workspace 0's same-named handler. Every non-terminal tenant run —
queued, running past deadline, or crash-orphaned mid-reconcile — is now excluded from dispatch,
the deadline sweep and startup's orphan re-probe, and counted as `parked_runs` in diagnostics,
waiting for a binary that owns it.

**The format guard checks the real journal shape.** v1.0.1 wrote snapshot format 2 on every
compaction, but the guard compared record versions only — so a rollback to v1.0.0 (which reads
snapshot 1) passed the guard and then refused to start. `--journal-format` now prints three
numbers — highest record version, highest snapshot (DRIX) version, and whether the binary parks
non-zero-workspace runs (`3 2 1` on this release) — and the guard refuses any binary whose
snapshot reader is older than the journal's, or that cannot park tenant runs the journal carries.
Diagnostics grew `journal_snapshot_version_max`, `journal_max_ws` and `parked_runs` so the check
works while the server is up.

**Restore accepts the agreed backup set.** The file list a backup may carry is one contract
across versions — generation files plus the journal-dir flats — so a backup taken after an
upgrade stays a legitimate rollback target.
