The Inspector is the single-page UI `durable-server` serves at `/inspector` when it's started with
`--ui-dir`. It's for looking, not scripting: a newest-first run list paged 50 at a time, each row
showing id, `op_key`, live state, step count and finish time — plus a cancel button on anything
that isn't terminal yet.

```sh not-run="needs the Inspector's assets built from the app first — npm install && npm run build in its directory, then --ui-dir at server start"
durable-server --journal journal --listen 127.0.0.1:58300 --ui-dir apps/inspector/dist \
  --handler step=http://127.0.0.1:58320/step
```

Then open `http://127.0.0.1:58300/inspector` — a local page, on a local server.

## The key, honestly stored

Paste a key into the field at the top and the list loads — the Inspector calls `GET /jobs` with it
as the Bearer token. Where that key lives is the security-relevant part, so it's precise:

- **`sessionStorage`, and nothing else.** Not `localStorage`, not a cookie, not the URL — the key
  dies with the tab, and a closed tab leaks nothing.
- **Use `DURABLE_READ_KEY`.** Browsing is a read; the read key is all it needs. A
  `sessionStorage`-scope leak then costs visibility, not control.
- **The API key only if you'll cancel.** `POST /jobs/{id}/cancel` needs the write key — the UI says
  so plainly if you cancel with a read key (`403`: *this key may only read*).
- **Or no key at all** on an `--open-reads` server — which, being loopback-only, means your own
  machine anyway.

## Same-origin by design

The Inspector is served by `durable-server` itself, so its API calls are relative — no CORS, no
configuration, no second origin to trust. It only speaks `GET /jobs` (paged with `before`,
newest-first) and `POST /jobs/{id}/cancel`; it has no admin surface and shows no submitted input —
`GET /jobs/{id}/spec` stays API-key territory and the UI never calls it.

What it won't do: submit work, read specs, touch admin routes, or persist anything beyond that one
`sessionStorage` slot. For everything it can't do, the [CLI](/cli/) and the
[HTTP API](/api/) are the tools.
